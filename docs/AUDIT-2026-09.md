# GradConnect audit — September 2026

A full pass over the codebase (Laravel 13 + Inertia/React, ~330 PHP files,
96 frontend files). This records what was found, what was fixed, and what was
deliberately left for later.

Test suite at the end of the pass: **472 passing, 0 failing, 5 skipped**
(Postgres-only). It was 442 passing / 3 failing at the start.

---

## The reported ParseError was not in this repository

A tester saw `ParseError: syntax error, unexpected token ";"` at
`app/Http/Requests/StoreEventRequest.php:8` on `/dashboard`.

That file is correct here, and always has been:

- Line 8 reads `class StoreEventRequest extends FormRequest` with no semicolon.
- No commit in the file's history contains the stray `;`.
- `php -l` passes on all 322 files.
- `storage/logs/laravel.log` contains no `ParseError`.

It was a local edit on the tester's machine. **Fix: delete the trailing `;` on
line 8, or re-pull the branch.**

Because a parse error in a file no route happens to load can reach a tester as
an unrelated 500, the project now has `composer lint` (a `php -l` sweep of
`app/`, `bootstrap/`, `config/`, `database/`, `routes/` and `tests/`) wired into
a GitHub Actions workflow alongside the test suite and the frontend build.

## Fixed

### Data loss

| What | Where |
|---|---|
| Editing a survey deleted and recreated every question, and answers cascade from questions — so any edit wiped every collected tracer-study response. Now diffed in place; removing or retyping an answered question is refused. | `SurveyController::update` |
| Deleting one staff account deleted their surveys, announcements, learning resources, events, scholarships, reports and student cases. Those creator columns now null out. | migration `2026_09_26_000001` |
| `pg_dump` ran without `--clean --if-exists`, so restoring into a populated database failed on every statement; `psql` ran without `ON_ERROR_STOP`, so it reported success anyway. A failed backup also wrote a `backup.created` audit entry. | `RunDatabaseBackup`, `RestoreDatabaseBackup`, `Admin\BackupController` |
| DOCX résumés were rejected outright on platforms whose type database reports the zip container; when they did get through, the file was stored as `.zip`, the extractor picks its parser by extension, found none, and marked the résumé failed with nothing shown to the user. | `StoreResumeRequest`, `ResumeController`, new `Rules\ResumeFileContent` |

### Privacy and access control

| What | Where |
|---|---|
| Employers received graduates' birthdate, gender, phone, address, student number and full résumé text, plus the pgvector embedding, in page payloads. Now explicit whitelists; email only for viewers who may see it. | `CandidatePresenter`, `CandidateController`, `TalentSearchController`, `JobPostingController`, `CandidateMatchController` |
| Applicants could attach another graduate's résumé to an application, which the employer's page then loaded. | `JobApplicationController` |
| Emails carried names and staff free text. Mail is now generic and links into the app; the in-app notification keeps the detail. | `app/Notifications/*` |
| Laravel's password-reset link carried `?email=`, leaking the address into browser history, referrer headers and proxy logs. | `AppServiceProvider` |
| The Gemini API key was sent as a URL query parameter, and connection errors log the URL. | `AiChatClient` |
| A department head with no college assigned saw institution-wide data in the program-outcomes page and its CSV export. | `ProgramOutcomesController` |
| Company editing was fully broken — `authorize('update')` with no policy always returned 403. | new `CompanyPolicy` |
| Unvalidated input reached `fill()`, letting a posting be moved to another company, a profile to another user, and a survey's creator be overwritten. | `JobPostingController`, `GraduateProfileController`, `SurveyController` |
| An admin could suspend, demote or delete themselves, or remove the last active admin; an unknown role name 500'd; the `sao` role could be deleted. | `Admin\UserController`, `Admin\RolePermissionController`, `AdminUpdateUserRequest` |
| Alumni Affairs held `candidates.search` but not `candidates.view_resumes`, so candidate links from search 403'd. | `RolePermissionSeeder`, migration `2026_09_26_000002` |
| Graduates could not message the SAO — `isStaff()` omitted the role. | `User`, `MessageController` |

### Correctness

- Survey answers were stored with no validation: out-of-range ratings, wrong
  types, missing required answers, and an array written into a string column
  could break the save. Rules are now built per question.
- Career readiness could report over 100%.
- The dashboard's pending-survey count ignored role and year targeting.
- Choice questions could not be saved at all: the form sends a comma-separated
  string where the request required an array, and no error was displayed.
- An employer could change the status of a withdrawn application, and an
  applicant could withdraw after being hired or rejected.
- A duplicate company could be created per partner (now also a unique index).
- `Skill::findOrCreateByName` slugged C, C++ and C# to the same `c`.
- End Date stayed editable while "currently working here" was ticked.
- N+1 queries on platform status, the dashboard, and the surveys index.

### Reliability

- No AI provider set an HTTP timeout (Laravel's default is 30s each), so a
  matching run over 20 candidates could overrun the job's own 120s limit.
- The queue's `retry_after` was **90s — shorter than the 120s job timeout**, so
  a slow job was handed to a second worker while the first was still running.
  `retry_after` (330) now outlasts the job (300), which outlasts the AI budget
  (240); a run past the budget keeps its similarity scores instead of dying.
- A Groq exception threw past the Gemini fallback, so the fallback only ran
  when Groq returned cleanly but empty.
- `phpunit.xml` blanks the AI keys, so a developer's real credentials in `.env`
  can no longer be spent by a test run.

### Mobile

The profile editor's four-tab bar needs more width than a 375px screen has. As
a plain row it pushed the whole page sideways, which is why a placeholder
appeared as "er at ACME Corp" — the page was panned right. Eight tables sat
directly inside `overflow-hidden` cards, clipping their action columns away
with no way to reach them. The public pages had no mobile menu at all, and
global search was hidden below `md` with nothing replacing it.

Shared primitives now carry this: `TableCard`, `ScrollTabs`, `Pagination`,
`CategoryBarChart`, `PublicNav`/`PublicFooter`/`PublicLayout`, the
`useDismiss`/`useBodyScrollLock`/`useMediaQuery` hooks, and `.form-grid` /
`.tap-target`.

One bug was only visible by measuring the rendered page: a grid item's default
`min-width: auto` let the hero's single mobile column size itself to 1035px,
so the headline was laid out that wide and then clipped by `overflow-hidden` —
invisible to a scroll-width check.

## Deliberately deferred

Low severity, no data or access risk:

- `Admin\SkillTaxonomyController:27` uses case-sensitive `like`, unlike the
  rest of the app on Postgres.
- `ResumeBuilderController:50` — two builds in the same second share a
  filename, so deleting either résumé removes the file for both.
- Graduation year is hard-coded to 2030 in two form requests, and
  `expected_graduation_year` has no upper bound.
- `routes/console.php` never schedules `backup:run`; backups are manual only.
- With no AI key configured, `/skills/resolve` accepts any skill name, so any
  signed-in user can create taxonomy entries.
- The landing page's statistics and testimonials are hard-coded, and one
  testimonial names a real company (Accenture). The AI match card was rewritten
  to use generic employer types for this reason; the testimonials were not.
- `@tailwindcss/vite` v4 is installed but unused (the build is Tailwind 3 via
  PostCSS).
- 41 pages hard-code light colours with no dark-mode variant. Dark mode is
  opt-in, so few users meet this.
- `ProfileEdit` submits `expected_graduation_year` and `address`, which no
  input renders.

## Not yet run against the development database

The five new migrations were verified end to end against a throwaway SQLite
copy, including the upgrade path from a database seeded with only `CCS` and
`COB`: existing ids are preserved, `COB` is renamed to `CBA` in place rather
than duplicated, and a college an administrator has renamed is left alone.

They have **not** been run against the local Postgres database, which was not
running during this pass. Back it up first, then `php artisan migrate`.
